# 2026-09-30 BUG

## 显示问题

【问题描述】

在鼠标滚动的时候，前面都能正常显示，到了后面（测试案例是大约是后半段，文件大小大约1200K），就会出现闪烁的情况。也就是说，滚动时候可以看见内容，但是停止滚动就加载失败，看起来一滚动就在闪烁，也许加载失败。

【问题原因】

[useFileWindow.ts](../src/hooks/useFileWindow.ts) 中缓存分片的 Map 用**字节偏移**做键（0、65536、131072…），而淘汰逻辑的中心点 `viewCenterChunkRef` 存的却是**分片索引**（0~18 的小数字）。

`evictFarChunks` 计算 `Math.abs(键 - 中心)` 时，几十万的字节偏移减去小于 20 的索引，距离约等于键本身——于是“离可视区最远”被错误判定为“字节偏移最大”。

**为什么恰好是 1200K 的后半段出问题**：1200KB = 19 个分片 > 缓存上限 10，淘汰才会触发。滚到后半段时，可见分片正是高偏移分片；停止滚动 100ms 后防抖计时器执行淘汰，把**正在显示的分片删掉** → 行变回 `--` 占位 → 触发重新加载 → 又被删 → 无限闪烁。滚动过程中你能看到内容，是因为 ensureRange 在不断重新拉取。前半段偏移小，被误删的恰好是远处分片，所以看起来正常。

【修复内容】

1. **统一键单位**：缓存 Map 改用分片索引做键，`fetchChunk` / `getBytes` / `readRange` / 预取 / 淘汰全部按索引运算，距离计算恢复正确——可见区及邻接分片（中心 ±2）永远不会被淘汰
2. **顺带加固**：分片加载失败自动重试 2 次（150ms/300ms 退避），避免偶发 IO 失败后可见区永远卡在占位符

现在滚到文件任何位置，淘汰只会清掉离可视中心最远的分片（约 640KB 内存上限不变），闪烁问题消除。
